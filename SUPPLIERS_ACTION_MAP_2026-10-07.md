## Three facts about the Ugat map that apply to almost every row

1. **`event_vendors` is not a node.** It is the joint **J7** "Event <-> Vendor (booking)" between TYPE-EVENTS and TYPE-VENDORS. Its own cluster (`event_vendor_*`: payments, payment_plan, working_notes, line_items) is in `ugat-concept.baseline.txt` as `map-backlog` - an admission, not a decision. So "is the data on the map?" = "J7 yes, everything hanging off it no".
2. **Not on the map at all** (`grep` count 0 in graph.ts, and no baseline line except where noted): `event_build_picks`, `event_category_decisions`, `event_bench_arrangement`, `vendor_lock_proposals`, `event_manual_vendors`, `vendor_invites` (the claim link), `vendor_follows`, `vendor_service_links`, `thread_service_interests`, `vendor_payment_methods`, `vendor_profile_views`, `build_requote_nudges`. `budget_builds` is only covered by the `budget_*` baseline line; `chat_messages` only by its own `map-backlog` baseline line.
3. **On the map:** TYPE-EVENTS (`events`), TYPE-VENDORS (`vendor_profiles`), TYPE-SERVICES (`vendor_services`), TYPE-THREADS (`chat_threads`, joint J5), TYPE-PROPOSAL (`vendor_proposals`), TYPE-AVAILABILITY (`vendor_schedule_pools`, J29/J30), TYPE-GEOGRAPHY (`regions`), J28 (`vendor_reviews`), J51 (`event_date_change_requests` + `_answers`: the Move / Unlock handshake), J24 (package items), J8 (service card -> taxonomy).

Repo rule 4 (CLAUDE.md) says a PR that touches `supabase/migrations/` must keep the map honest. None of the NEW items below needs a migration except where stated, so the map would not move - but several tables the prototype leans on (builds, picks, claim links, follows) are invisible to the map today. That is a pre-existing gap, not caused by the prototype.
