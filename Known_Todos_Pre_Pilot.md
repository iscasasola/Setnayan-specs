## TODO hygiene rules (locked for future audit passes)

Adopting these rules so the next audit cycle (V1.5+ ramp-up) has a
clearer signal-to-noise on this surface:

1. **TODO marker format:** `// TODO(<iteration>): <one-line intent>` where
   `<iteration>` is the 4-digit folder slug (`0011`, `0012`, etc.) or
   `V1.x` / `V1.1` for cross-iteration scope. Keeps grep-by-iteration
   trivial.

2. **JSX TODO format:** `{/* TODO(<iteration>): <one-line intent> */}`
   inside JSX. Confirmed by spot-check that these are stripped from
   rendered HTML output.

3. **No new TODOs in pilot-path code** without an entry in this doc.
   When adding a TODO to a pilot-path file (auth, signup, event creation,
   guest list, vendor browse, checkout, day-of guest, basic dashboard),
   the engineer must add a row to Category 4 of this doc.

4. **No user-visible TODOs.** All TODOs live in comments — `// ...` or
   `{/* ... */}`. Never in JSX text content, alt text, aria-label, or
   placeholder attributes. Per [[feedback_setnayan_no_dev_text_post_launch]].

5. **Retire when shipped.** When a TODO category's engineering lands
   (e.g., Papic native ships), the implementing PR retires the matching
   rows here in the same commit. Keeps this doc as a living index.
