## 1. The lifecycle law

Every record in the platform has **one birthplace surface, one home (a Postgres table, sometimes plus an R2 object referenced by an `*_r2_key` column), and many read windows** — sharing is almost always a *read* of the home row, not a copy. Births are enforced three ways: **DB triggers** for automatic siblings (auth user → `public.users`, vendor signup → `vendor_profiles` + founding team seat, event insert → `event_join_tokens`, vendor insert → Bark `screen_name`); **canonical RLS patterns** (Pattern A self-only `user_id=auth.uid()`, Pattern B `current_event_ids()`, vendor-org `current_vendor_ids(min_role)`) for member reads; and **SECURITY DEFINER RPCs** wherever an accountless actor must write (guest captures, tags, token burns, seat claims). The big asterisk: most sensitive writes actually ride the **service-role admin client with app-side auth checks**, so RLS is frequently a backstop rather than the live gate — and the entire guest side authenticates with a **signed JWT cookie**, never an auth row. Two single-source locks hold well: **R2 is the system of record for bytes** (Drive is an explicit copy layer; guest-facing derivatives are re-encoded, stripping EXIF) and **`orders.status` is the single source of entitlement** via `eventSkuActive`. Where the law breaks, it breaks by *denormalized copies synced in app code* (pax counts, roles, `vendor_profiles.services`, activation flags) — all catalogued in §4.

## 4. Gaps & duplications (prioritized, critic-verified)

### 🔴 Privacy / security

1. **Payment screenshots land in the PUBLIC R2 bucket** — `bucketForPrefix` (`lib/storage.ts:69-76`) matches singular `payment-screenshot/` but both writers use plural `payment-screenshots/…` (`checkout/actions.ts:456`, `orders/actions.ts:482`); proofs fall through to the public `media` bucket.
2. **Geo/EXIF stripping is convention, not enforcement** — `lib/mediaPipeline.ts` posts capture metadata as FormData that `/api/upload` (JSON-only) never reads; `papic_photos.geo_*` have no writer; couple ZIP export and both Drive-copy paths stream **original bytes with EXIF intact**; only guest-facing derivatives are safe (sharp re-encode).
3. **Unauthenticated push route** — `/api/notify` (DB webhook target) accepts posts, sends push, and writes `chat_threads.last_push_notified_at` with no auth.
4. **RA-10173 consent race at signup** — `public_summary_consent_at` write polls 5×100 ms for the trigger row then silently drops the consent timestamp (`signup/actions.ts:282-300`); also a **scope mismatch**: user-level column toggled from event-scoped pages.
5. **Email verification bypass** — every signup auto-confirmed via admin API (`signup/actions.ts:305`); blacklist is the only abuse gate.
6. **Anonymity leak** — pre-reveal thread lists mask the vendor name but pass the real `logo_url` unconditionally (`messages/page.tsx:235` → `thread-list-card.tsx:99`).
7. **Guest write trust anchor is one JWT cookie** — all guest self-service writes (RSVP, selfie, tags, kwento, pabati) ride service-role with the signed cookie as the sole gate; RLS deny-by-default is deliberately bypassed.
8. **Biometric RLS boilerplate** — `guest_face_enrollments` write policy carries `OR is_admin()`, contradicting the face-data-off-limits rule; holds only because zero admin surfaces touch it.
9. **Un-rotatable event QR** — nothing ever writes `event_join_tokens.revoked_at/expires_at`; a leaked event QR is permanently valid (all 4 read sites honor fields no writer sets).
10. **Couple can hard-delete accepted threads** — `withdrawInquiry` cascades all messages; the vendor loses the record of an unlock they paid tokens for.
11. **Public session-less seat lookup** — `/api/seat-lookup/[slug]` + table-token `/[slug]/seat` serve name→table with no cookie (deliberate, but a PII window worth an owner nod).
12. **No couple-side PII read trail** — admin views are logged (`admin_data_access_log`); couple/coordinator reads of guest emails/dietary/mobile are not.

### 🟠 Money integrity

13. **0034 reconciliation matcher never built** — no `payment_inbox_messages` table, no `match_inbox_to_order` SQL; only the client-side paste matcher (2-tier, zero persistence); inbound bank/GCash notifications are never stored.
14. **Orders insert has no idempotency key** (acknowledged in code) — a retried submit mints a duplicate order with a fresh reference.
15. **Ledger coverage is partial and unread** — legacy, papic, and branch orders never append `order_ledger`; no UI reads it (only activation idempotency lookups).
16. **Comp/self-comp orders born `paid`** bypass the admin payments queue entirely; ₱0 papic unlock orders born `fulfilled` do the same.
17. **Vendor purchases (subs + token packs + branch fees) collect no screenshot** — weaker evidence trail than the couple flow.
18. **Activation state duplicated** — `orders.status` (via `eventSkuActive`) vs copied `events.setnayan_ai_active/*` columns; non-fatal hook failure = silent divergence.
19. **Payout layer is legacy-wired** despite 0% commission (breakdown denormalized onto `orders` columns; `lib/payouts.ts` dispatcher still live for `vendor_profile_id` rows).
20. **Voucher cap check not atomic** with the uses bump (CHECK constraint is the backstop).
21. **Spec drift**: corpus still promises "100 free tokens on verification" — retired in code (`20270110320020`).

### 🟡 Locked-decision drift

22. **"No public API endpoints in V1" is breached** — `/api/v1/vendors` is live, no-auth, CORS-open; `/api/v1/events|guests|me` serve real data on bearer keys.
23. **"vendor_profiles creation is trigger-only" is stale** — three shipped app insert paths (open-shop, claim finalize, admin staging) + open-shop re-implements the trigger's provisioning in app code (drift-prone mirror).
24. **Legacy per-section service-card forms still live** on My Shop alongside the atomic RPC — the "one atomic tx replaced them" story is half-true.
25. **Stale-event rule (14d/30d) + `events.archived`**: definition-only — no detector, no cron, no writer; anon onboarding keeps minting ghost events with nothing reaping them.
26. **Coordinator per-thread join (0019)** unbuilt — enum value exists, `current_thread_ids()` never used, coordinators cannot post.
27. **`adminAcceptInquiry` bypasses the token burn** — accepted threads for demo vendors with no `vendor_event_unlocks` row or ledger entry.

### 🔵 Duplication / copied-instead-of-derived

28. `users.email` mirrors auth email; anon-convert overwrite is best-effort — a permanent account can keep `anon+…@anon.setnayan.local` forever. Also `account_type` lives in both auth metadata and `public.users` with no post-birth sync.
