## 6. Pricing-architecture policy (carried, owner now on Apple Developer)

- **Web-checkout, NOT in-app IAP.** Route every bundle/SKU purchase through web checkout (Apple Pay on web = 0% store cut); iOS IAP on digital goods = 15–30% → gut the ~95–99% margins. Native app deep-links to web. Decide the IAP-vs-web split BEFORE App Store submission (anti-steering = gating risk).
- **Native app → pay on the website (DECIDED 2026-06-16 · PR #1538; supersedes the +30% markup, #1458 CLOSED).** The iOS/Android app does NOT charge in-app — the checkout drawer hands off to the **website** (external browser, `window.open('_system')`) where the buyer pays out-of-app via **BDO/GCash at the BASE price**. Why not IAP+30%: Apple/Google forbid selling digital goods in-app via an external rail (App Store rejection), and the website is the cheaper path (base price, 0% store cut, 0% processor — manual reconciliation). So **app and web both = base price**; the app is just a doorway to the web payment. No markup, no Apple/Google cut. Follow-up: auth continuity on the external-browser hand-off (one-time deep-link). The earlier +30% markup (`lib/platform-pricing.ts`) is retired — kept here only as lineage.
- **All prices admin-managed.** Every value above is set in the admin catalog (`/admin/pricing`), never hardcoded (the plumbing for this shipped PRs #1431/#1441/#1444). The server charges the catalog price for every SKU + bundle.
