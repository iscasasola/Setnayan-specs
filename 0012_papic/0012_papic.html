Iteration 0012 · What ships

Papic V1

Native iOS + Android candid-capture for Filipino weddings. Three or five trusted friends shoot like second photographers using the rear camera only. QR-driven tagging keeps the gallery navigable. Untagged photos still flow to the couple. The Custom Monogram Pack from 0011 replaces Setnayan's logo with the couple's monogram on every share, download, and reel.

The four capture gestures

Tap
Photo, no flash. Snappy — fires on touch-up.
Drag up
Photo with flash. Single pop synced to the shutter.
Drag right
5-second clip on release. Records the full 5 seconds continuously — cannot be cut short.
Drag right → drag up
Chord gesture before release. 5-second clip with flash; torch on for the full 5 seconds.

Papic dashboard — the patiktok-style home screen

The camera is no longer the app's home screen — it's a deeper state entered from the dashboard. The dashboard is the papic's workspace between captures: a TikTok-style vertical feed with four tabs and a single prominent camera-entry button. There is no central curation hub; every papic seat sees the same feed and acts on the same primitives.

Untagged tab — default landing

  • Vertical feed of untagged photos (My captures / Event-wide toggle)
  • Each card: thumbnail · suggested face match · confidence · source seat
  • One-tap accept the suggestion or scan a QR to override
  • Skip is safe — untagged photos still ship to the couple
  • Event-wide scope downloads thumbnails only (≈ 22 MB / device / event)
  • Cross-papic tagging means couples open to a near-tagged gallery

Queue tab — my pipeline

  • Per-file status: uploading / done / weak-mode-held / failed
  • Progress bars for in-flight items; bandwidth mode badge
  • Bulk retry for items stuck on weak mode after 10 min
  • Disappears after upload completes (settles into Uploaded)

Uploaded tab — my contributions

  • Grid of this seat's captures, mine only
  • Tag count + clip marker per tile
  • Tap to retag, favorite, or delete (within 24h)
  • Drives the post-event "My contributions" view referenced in V1 ships

Guests tab — patiktok QR feed

  • One full-screen card per guest: avatar · name · role · table · QR
  • Search bar at top; swipe up/down to page through
  • "Tag in last 5 captures" applies guest to recent shots without leaving dashboard
  • Same data as the camera's Pick button, presented as a feed

Camera entry. A pulsing camera FAB anchors the lower-right of every dashboard tab. Tapping it enters the capture screen with the gesture shutter, viewfinder, last-5 strip, and the existing Pick / Torch / Tag drawer affordances. The camera has a Dashboard chevron in the upper-left to return.

Bandwidth budget. 5 papic × ~1,500 photos/event × 15 KB thumbnail ≈ 22 MB per device for the cross-papic untagged view. Originals stay scoped to the capturing seat. Adaptive compression already establishes the thumbnail-first pattern; the dashboard reuses it.

Pro Camera Bridge — DSLR pairing

One bridge unlock turns one phone seat into a phone+DSLR pair. The phone keeps every responsibility it had in V1 — gesture shutter, tag drawer, face detection, EXIF stamping, adaptive compression, offline queue, upload — but the optical capture surface moves to the DSLR. The phone fires the DSLR's shutter via the vendor's WiFi SDK; the DSLR captures the file; the file transfers to the phone over WiFi; from there everything proceeds as the phone-internal path. 1 phone : 1 DSLR. WiFi only in V1.

Vendor SDKs sit behind a single CameraBridge abstraction. The phone-internal camera is a fifth implementation of the same interface, so the gesture shutter, last-5 strip, tag drawer, and face detection don't need to know whether they're driving a Canon body, a Sony body, or the phone's own sensor.

Face detection — layered enrollment + auto-tag

1 · RSVP profile photo

  • Source: already required in 0001 / 0002
  • Quality: baseline (~90% guest coverage)
  • Friction: zero — already collected

2 · Pre-event guest portal

  • Source: 1–3 photos uploaded via personal invitation page
  • Quality: medium-to-high (face-forward, lit)
  • Friction: low — opt-in

3 · Check-in kiosk

  • Source: laptop / tablet at venue entrance
  • Quality: highest — controlled lighting and pose
  • Friction: low — folds into arrival flow

Confidence thresholds

  • ≥ 0.85 → auto-tagged with source='auto_face'
  • 0.65 – 0.85 → suggested tag in last-5 strip
  • < 0.65 → photo uploads untagged; existing QR / Pick / table fan-out paths still work

Capture metadata + adaptive compression + offline queue

Per-capture metadata

  • captured_at — NTP-synced device clock at shutter release
  • geo_lat / geo_lon / geo_accuracy_m — Core Location / FusedLocation, max age 60 s
  • device_model
  • paired_camera_brand / paired_camera_model — null on phone-internal
  • Written to EXIF on JPEGs, QuickTime atoms on MP4s, photos table, SQLite WAL
  • Geo stripped on outbound shares; original on R2 retains it

Adaptive compression — 3 modes

  • Strong (> 5 Mbps): originals pass through unmodified; RAW uploads at full resolution
  • Medium (1 – 5 Mbps): JPEG re-encoded at 80%; H.264 CRF 23 1080p; RAW queued for later
  • Weak / offline (< 1 Mbps): queue everything locally; thumbnails ship first; originals follow when bandwidth recovers
  • Mode switches sticky for 30 s minimum dwell to prevent oscillation

Offline queue

  • SQLite WAL persists across app suspend, force-quit, reboot, and battery handoff
  • Wakes on network change via NWPathMonitor / ConnectivityManager.NetworkCallback
  • Exponential backoff: 5 s → 10 s → 30 s → 60 s → 5 min steady
  • 7-day TTL; "couldn't deliver" prompt with bulk re-try after expiry
  • Top-bar chip surfaces queue depth + network mode: "12 queued · 3 uploading · medium"

Privacy guards

  • Couple-level geolocation toggle in event settings (default ON; off for private home weddings)
  • Geofence sanity check: photos > 50 km from venue drop their geo metadata server-side
  • Face vectors per-event-scoped; never reused across weddings
  • Guest "Delete my face data" revokes within 5-minute cache refresh
