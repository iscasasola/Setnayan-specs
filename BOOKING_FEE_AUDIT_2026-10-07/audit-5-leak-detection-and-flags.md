## Summary per rule

- Rule 1 (supplier with several booked-but-unsettled events flagged for admin): **PARTLY**. `/admin/booking-fees` + the `booking-fees` queue badge list per-charge pending fees; the `fraud_signals` pipeline and `/admin/fraud` page are an existing flag host. Nothing groups by supplier, counts events, or sees bookings that never opened a charge.
- Rule 2 (manual add / self-added budget matches a quote already received, so fee applies): **NOT FOUND**.
- Rule 3 (we saw them first, so a manual add matching a viewed or inquired shop is sourced): **PARTLY**. The writer (`recordVendorProfileView` with `event_id`, and thread `inquiry_source`) and the linking path (`attachMarketplaceVendorToCategory` stamping `source='host_marketplace_search'`) exist, but the fee rule `booking_fee_attribution_for` reads only `chat_threads.inquiry_source` and never views.

## To build

1. Rule 3 core (migration needed, one function): new version of `booking_fee_attribution_for(vendor, event)` that also returns 'sourced' when a `vendor_profile_views` row exists for (vendor_profile_id, event_id) with a viewed_at before the `event_vendors` row's creation, OR the `event_vendors.source` is 'host_marketplace_search' or 'auto_cascade_from_finalize'. Reads `vendor_profile_views`, `event_vendors`, `chat_threads`. Mirror in `SOURCED_INQUIRY_SOURCES` (the DB test asserts agreement). Note: views are only recorded for a signed-in couple with an active event, and attribution is frozen once at `booking_fee_ledger.attribution_frozen_at`, so freezing must wait until lock.
2. Rule 3 gap, manual-name link (no migration): on `createManualVendor` / `attachManualVendorToCategory` and the budget-line door (`lib/event-costs.ts`), match the typed name or an existing `vendor_profiles.business_name` via the same lookup as `searchMarketplaceVendorsByName` and set `marketplace_vendor_id`. Without that link the fee path skips (`not_verified_vendor`) and no charge can exist.
3. Runs at lock or deposit-acknowledgement; result feeds attribution. Pure SQL function, so a migration (function only, no new table).
4. Rule 2 evidence row (migration): a small table (or JSONB on `booking_fee_ledger`) recording why a booking was re-attributed (matched proposal id, view id), so the admin and the vendor can see it. Needed because attribution is frozen and "immutable".
