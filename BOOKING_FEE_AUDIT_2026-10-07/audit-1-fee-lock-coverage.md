# Audit 1 — booking-fee lock coverage (supplier surfaces)

Sources: archive of origin/main `apps/web/app` (scratchpad `btn/`) + `git show/grep origin/main` for `apps/web/lib` and `supabase/migrations`. Read-only.

## The gate, as it exists
- Rule: `eventAccessUnlocked` / `resolveEventAccessStage` in `lib/event-access-stage.ts`; switch `resolveFeeEnforcement` (env `NEXT_PUBLIC_FEE_UNLOCKS_EVENT` OR `platform_settings.fee_unlocks_event_enforced`) in `lib/vendor-event-fee-access.server.ts`.
- Page wrapper: `resolveEventFeeGate` → `EventLockedPage` / `EventLockedByFee` (`vendor-dashboard/_components/event-locked-by-fee.tsx`).
- Server-action wrapper: `eventFeeBlocksAction` (returns `FEE_LOCKED_ACTION_MESSAGE`).
- SQL gate: `public.vendor_event_fee_gate_stage` (migration `20271236283573_seal_the_brief_in_sql`), used ONLY inside 5 RPCs: `get_vendor_event_brief`, `get_vendor_mood_board`, `get_vendor_seat_plan`, `get_vendor_cocktail_editor`, `get_vendor_catering_metrics`. `git grep fee_gate_stage` finds no other caller in migrations. No RLS policy references it.
- The repo guard `vendor-dashboard/the-fee-unlocks-the-event.test.ts` pins only `GATED_PAGES` (10 pages) and `GATED_ACTIONS` (5 action modules). Anything outside those two lists is unguarded by that test; that is where the GAPs below sit.
- NOT FOUND: the live value of `platform_settings.fee_unlocks_event_enforced` / env flag in production (not readable from a session). Brief says ON; every OK below is conditional on it.
- Minor drift: `vendor-dashboard/messages/[threadId]/page.tsx` derives `briefStage` from `isFeeUnlocksEventEnabled()` (env only), not `resolveFeeEnforcement` — if only the DB switch is on, step 1 of the quote will not announce withheld fields. Cosmetic, not a leak.

## GAP list and fix (one line each)

1. clients/[eventId]/calendar.ics route GET: call `resolveEventFeeGate` and 403 (or strip `LOCATION`) unless `stage === 'unlocked'`.
2. on-the-day/page.tsx `ConfigureEventView`: run `resolveEventFeeGate` before returning it (mount `EventLockedPage`), same as the today branch.
3. customers-roster `r.place` and vendor-overview `placeLabel`: show `region` (area) unless the event's gate is `unlocked`; use `resolveEventFeeGates` for the list (one query).
4. messages/[threadId] `VendorEventDayPrepCta` / `prepareVendorEventDay`: add `eventFeeBlocksAction` inside the action and hide the card when locked (thread page itself must stay ungated).
5. RLS: add a fee-aware predicate (via `vendor_event_fee_gate_stage`) to `event_schedule_blocks_booked_vendor_read` and the other booked-vendor read/insert policies, or accept that the raw table remains the open door the brief seal was meant to close.
6. Every ungated server action module below needs a first-line `eventFeeBlocksAction` and an entry in `GATED_ACTIONS` of the guard: `clients/[eventId]/actions.ts` (schedule/handover/change-order/challenge/complete only, NOT money/lock), `script-actions.ts`, `production-sheet/actions.ts`, `cocktail/actions.ts`, `editorial-media/actions.ts`, `finalization-actions.ts`, `booth-event-actions.ts`, `stage-notes-actions.ts`, `on-the-day/actions.ts` (song desk via `requireSongDeskAct` + 5 set functions), `floorSeatByQr`.
7. `app/_actions/run-of-show.ts` `advanceScheduleBlock` / `fetchRunOfShowBlocks`: add a supplier-only fee check (couple callers must stay unblocked).
8. `api/vendor/papic-capture` and `api/vendor/papic-portfolio-import`: resolve the shop + event and refuse with `FEE_LOCKED_ACTION_MESSAGE` when `eventFeeBlocksAction` returns non-null.
9. Customer card `OverviewTab`: wrap `BoothPosterCard`, `BoothStudioCard`, `VendorChallengeSection`, `BoothEventSection`, and the flag-OFF `VendorCompletionCard` in `feeUnlocked` (flag-ON already does the completion card).
10. `manpower/surface.tsx` + `claim_manpower_gig`, `api/crew/register-device`, `appointments-actions.ts`: owner decision whether these are "functions that should only work after the booking fee"; if yes, gate as above.
11. Add all newly gated pages/actions to `GATED_PAGES`/`GATED_ACTIONS` in `the-fee-unlocks-the-event.test.ts` so the omission becomes loud (the guard currently lists 10 pages + 5 action modules and nothing else).
