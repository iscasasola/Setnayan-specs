## 3. Setnayan Concierge — canonical V1 spec (locked 2026-05-17)

This is the most-touched feature this week. Single point of truth:

### Pricing

| | |
|---|---|
| **SKU** | `concierge_complete` |
| **Price** | **₱4,999** (499,900 centavos) |
| **Access duration** | Wedding-anchored — `LEAST(GREATEST(wedding_date + 30d, activated_at + 12mo), activated_at + 24mo)` |
| **Floor** | 12 months from activation (guarantees minimum runway even with NULL wedding_date) |
| **Cap** | 24 months from activation (protects margin · triggers advisory for >24mo engagements) |
| **Renewal** | Always full ₱4,999 — no loyalty discount, no extension rate |
| **Auto-renew** | Not in V1 (deferred to V1.5 with GCash Merchant API) |

### Free trial

| | |
|---|---|
| **Duration** | **3 days** card-less (no payment method required) |
| **Scope** | **One trial per account** (tracked on `users.concierge_trial_used_at`) — NOT per event |
| **Block conditions** | Trial-start fails if account already used trial OR enforcement_level ∈ {trial_banned, full_banned} OR cross-account similarity check fires |
| **On similarity hit** | Trial slot NOT consumed (so falsely-flagged users can still trial after admin clear); flag inserted into `concierge_abuse_flags` with `status='pending_review'` |

### Anti-abuse — tiered enforcement (admin-actioned via new 0023 § 3.11 tab)

| Strike | Enforcement level | Effect |
|---|---|---|
| 1 | `'warning'` | Audit only · trial still works · in-app notification |
| 2 | `'trial_banned'` | Trial blocked · purchase still allowed · banner + appeal CTA in Settings |
| 3+ | `'full_banned'` | Trial AND purchase blocked · explanatory copy + appeal CTA |

**Detection signals on trial-start attempt** (weighted, composite score ≥ threshold blocks):

- Same `wedding_date` (high)
- Same venue name (fuzzy match · token-set ratio ≥ 0.85) (high)
- Same venue address (high)
- Same couple-name overlap (high)
- Same phone number (CRITICAL · auto-flag)
- Same payment-method fingerprint (CRITICAL · auto-flag)
- Same device fingerprint / IP within 14-day window (medium)

**Admin actions** — `adminClearConciergeFlag` · `adminConfirmConciergeAbuse` · `adminLiftConciergeEnforcement`. Single-admin authority per § 4.3 (reversible decisions don't require two-admin).

### Schema additions (full migration)

```sql
-- events table
ALTER TABLE events
  ADD COLUMN concierge_status TEXT
    NOT NULL DEFAULT 'diy'
    CHECK (concierge_status IN ('diy', 'trial', 'active', 'expired')),
  ADD COLUMN concierge_tier TEXT
    CHECK (concierge_tier IN ('complete')),                    -- Essentials retired 2026-05-17
  ADD COLUMN concierge_activated_at TIMESTAMPTZ,
  ADD COLUMN concierge_expires_at TIMESTAMPTZ,
  ADD COLUMN concierge_long_engagement_advised_at TIMESTAMPTZ;

-- users table
ALTER TABLE users
  ADD COLUMN concierge_trial_used_at        TIMESTAMPTZ,
  ADD COLUMN concierge_abuse_strike_count   INT NOT NULL DEFAULT 0,
  ADD COLUMN concierge_enforcement_level    TEXT NOT NULL DEFAULT 'none'
                                            CHECK (concierge_enforcement_level IN ('none', 'warning', 'trial_banned', 'full_banned')),
  ADD COLUMN concierge_enforcement_at       TIMESTAMPTZ,
  ADD COLUMN concierge_enforcement_by       UUID REFERENCES users(user_id),
  ADD COLUMN concierge_enforcement_reason   TEXT;

-- abuse flags audit table
CREATE TABLE concierge_abuse_flags (
  flag_id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  flagged_user_id   UUID NOT NULL REFERENCES users(user_id),
  matched_user_ids  UUID[] NOT NULL,
  similarity_score  NUMERIC NOT NULL,
  signals           JSONB NOT NULL,
  status            TEXT NOT NULL DEFAULT 'pending_review'
                    CHECK (status IN ('pending_review', 'cleared', 'confirmed_abuse')),
  created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  reviewed_at       TIMESTAMPTZ,
  reviewed_by       UUID REFERENCES users(user_id),
  admin_notes       TEXT
);
CREATE INDEX idx_concierge_abuse_flags_status ON concierge_abuse_flags(status, created_at DESC);
```

**Server actions** (apps/web/app/dashboard/profile/concierge/actions.ts):

- `activateConcierge({eventId, orderId})` — flips to `'active'`, computes expires_at via formula
- `cancelConcierge({eventId})` — marks `cancellation_requested_at`; access continues until natural expiry
- `startConciergeTrial({eventId})` — similarity check + account-cap check + enforcement check; on pass flips to `'trial'` for 3 days
- `recomputeConciergeExpiry({eventId})` — fires from `events.wedding_date` update; extend-only

**Admin actions** (apps/web/app/admin/concierge-abuse/actions.ts):

- `adminClearConciergeFlag({flagId, adminUserId, notes})` — false positive · no strike
- `adminConfirmConciergeAbuse({flagId, adminUserId, notes})` — strike + auto-bump enforcement level
- `adminLiftConciergeEnforcement({userId, adminUserId, notes})` — decrement strike count (appeal flow)
