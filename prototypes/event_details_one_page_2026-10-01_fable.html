Event Details — one clean page

Owner, 2026-10-01: "do we have a button for this. Event Details? where data they fill up like what are locked suppliers, services, on boarding, date, etc is compiled in 1 sheet" and, later, "purchases, budget, dates, etc". So: the shipped Personalization page (reached only through the small "Event settings" line) becomes Event Details, a button on Event Home beside the event name. One scrolling page of compact read-out rows, label · value — information only. Nothing is edited here; each section carries one quiet Open … › to the app that owns those facts (a deliberate exception to the no-link-out rule, because this page is a read-out). Every row reads the same field its app writes, so Event Details and the app can never disagree. Nothing shipped is dropped: names · kind · area · date · venues · guest count · how guests get in · edit deadline · how you see costs · budget · suppliers · services · Event Hub look · Love Story · dress code · RSVP · Put this away are all here. Sample: Claire & Indalecio · Friday 18 December 2026 · sample data only.

§What is kept, what moved, what is open

Kept from the shipped page — nothing dropped, nothing edited here

  • The basics (names · region → "Area" · style/feel → folded into the Event Hub theme row · budget → Budget › Target). The "who is being celebrated" and "repeat" controls only appear for the event types that show them today; a wedding shows neither, so they are not drawn.
  • Your wedding (kind · parish · reception · guest count · date) → The basics + Venues + Guests + Key dates. Locked-by-booking → the lock glyph and the sheet in frame 4, with the shipped Contact support.
  • Guest list & pricing (edit deadline · Realtime / Final only) → Guests › Guest list closes · How you see costs. Final only stays one dropdown of two.
  • From your onboarding (budget band · monogram · music · services picked) → Budget › Target · Your Event Hub look (monogram sits inside the Theme editor, as the Maker holds it) · Your suppliers.
  • Put this away → last, quiet, as shipped.
  • One source per row — every row names the field its app already writes: Schedule blocks for the three times, the Guest list mode for "How guests get in" and RSVP "Who can reply" (one fact, two rows, same field), Mood Board dress_code_config for What everyone wears, locks on the Bench for suppliers, orders for Purchases, the Maker's theme · palette · font roles · music · cover · monogram for the look.
  • What the shipped page edited is now opened, not edited — names · area · style · budget target (DetailsForm), kind · venues · guest count · date (GovernedFields), edit deadline · cost view (PaxSettingsCard) each have an Open … › on their section. Only Put this away keeps its button, as shipped.

Open owner questions

  • The name clash. The Maker already has a Details tab (Details › Your event · Venues). This page is called Event Details anyway. Rename the Maker tab (e.g. Your event), or accept two "Details"? Drawn as Event Details.
  • Key dates — "your set-up price window if any". This sample event has none, so no row is drawn. When one exists, it would sit in the same list as Price window closes · date. Confirm the wording.
  • How many supplier payments to show. Drawn: the next two. Three is also fine; all of them belongs in Suppliers, not here.
  • Who sees Budget. The shipped page hides the budget target from a coordinator who is refused the figure. Here: a coordinator opening Event Details would see the Budget section with Hidden by the couple in place of the numbers. Confirm.
  • "Open Services ›" and "Open Orders ›". Services (Event Hub Pro · Setnayan AI · Papic) and Purchases each need a page to open; drawn as Services and Orders — confirm which shipped pages those are (the More sheet's rows, the orders list).
  • The lock sheet keeps "Contact support". It is the one tap on the page that opens anything. Keep it, or make locked rows plain read-outs too?
