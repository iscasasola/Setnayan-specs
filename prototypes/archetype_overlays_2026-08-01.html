The overlay grammar — seven archetypes for every dialog, sheet and notice in the app

~55 files currently render an ad-hoc dialog, sheet or modal with no shared rules. They collapse into the seven types below. Each is live on this page at both breakpoints — mobile 390 (bottom sheets, the Shopee/GCash-native form) and desktop 1280 (centred dialogs, side drawers, anchored popovers). Every demo really opens, traps focus, and returns it to its trigger. Light theme only; the lightbox alone is obsidian, because media reads better on dark — not because a dark mode exists.

01 / 07

Confirm dialog — destructive actions only

The only overlay allowed to interrupt. It exists for exactly one job: making the user read the name of the thing they are about to destroy. Anything non-destructive that currently uses a confirm gets demoted to an optimistic action + Undo toast (archetype 02).

Trigger
A destructive control — delete, cancel booking, revoke, regenerate QR (which invalidates the old one), remove a person.
Dismiss
Explicit only: the Cancel button or the labelled Keep action. Deliberately NOT: backdrop click, Esc, swipe-down. A refused gesture shakes the panel (180ms) so the refusal reads as intent, not a bug. Esc-to-confirm never exists anywhere.
Focus
Focus moves to Cancel (the safe default) on open, is trapped, and returns to the trigger on close. role="alertdialog" · aria-modal · aria-labelledby · aria-describedby
Scrim
rgba(30,26,18,.44), page scroll locked. The scrim does not accept the click — that is the point.
Mobile vs desktop
Mobile 390: bottom sheet rising from the touch point, stacked full-width buttons, destructive on top. Desktop 1280: centred 460px dialog, buttons right-aligned, destructive last.
Stacking
May open on top of any other overlay (e.g. a remove button inside the guest picker). The overlay underneath dims a step further, becomes inert, and is restored when the confirm resolves. A confirm never opens another overlay.
Designer's note

The destructive button is #B65A3A (negative), never terracotta. Terracotta #C24E25 is the "go" colour everywhere else in the app; if delete were terracotta, two years of learned muscle memory would press it. Cancel is the focused default, so Enter-mashing is always safe.

The plaque names the object — "Maria & Jomar's kasal", not "this item" — with its guest count or booked date underneath, because the count is what makes a hand hesitate. Copy pattern: heading = verb + named object + ?, body = what is lost, button = verb + noun ("Delete event"), never a bare "OK"/"Yes".

02 / 07

Toast / snackbar — the receipt for an optimistic action

Fires after the UI has already committed optimistically. It confirms, offers Undo where the action is reversible, and leaves. It never asks a question and never blocks. Where the old code used a confirm for a reversible action, this archetype replaces the confirm entirely.

Trigger
Completion of an optimistic action — guest removed, table renamed, payment logged, invitation queued. Never opens on its own schedule.
Dismiss
Auto-dismiss ~4s (visible lifetime bar; timer pauses on hover/focus) · horizontal swipe · the labelled close. Esc dismisses the newest toast. Undo dismisses and reverts.
Focus
Never steals focus. Announced via a polite live region (role="status" aria-live="polite"). Undo is reachable by Tab while the toast lives; the pause-on-focus keeps it catchable.
Scrim
None. No scroll lock. The page stays fully interactive.
Mobile vs desktop
Mobile 390: bottom-centre, above the tab bar, full-width minus 14px gutters. Desktop 1280: bottom-left, max 400px, newest at the bottom.
Stacking
Max 2 visible; older toasts collapse early. Toasts render above every overlay except the lightbox stage. They never stack into a tower.
Designer's note

A toast must never be the only place an error appears. A toast is gone in 4 seconds; an error is not. Every failure that shows a toast also renders a persistent inline error at the point of failure — the toast is the announcement, the inline error is the record. The "rename" demo below shows the pair.

Ink-dark surface (#2C2A29) with cream text — the one deliberate inversion in the light app, so a toast is findable in peripheral vision. Undo is gold-accent Space Mono, matching the "highlight" role gold plays everywhere else.

03 / 07

Command palette — ⌘K, everything by name

One search box over everything the signed-in account can reach: events, guests, vendors, actions, pages. Selecting navigates or acts — it is the only overlay allowed to navigate. The existing home command bar and the vendor category search overlay both become skins of this one component.

Trigger
⌘K / Ctrl K anywhere · the labelled Search control in the chrome. (Try ⌘K now — it opens in the desktop frame below.)
Dismiss
Esc · backdrop click · selecting a result. Clearing the query does not close — it returns to Recents.
Focus
Focus lands in the input on open and stays there; ↑↓ move a visible selection ring (2px link-blue) via aria-activedescendant; Enter commits. Combobox + listbox pattern; focus returns to the trigger on close.
Scrim
Standard scrim, scroll locked. Desktop panel drops from the top (64px down), not centre — eyes are already at the top where search lives.
Mobile vs desktop
Mobile 390: full-height sheet, input pinned top, keyboard pushes results. Desktop 1280: 620px top-anchored panel, max-height 440px.
Stacking
Opens above everything and closes before acting — a palette action that needs a picker or confirm opens it after the palette has closed. Nothing opens on top of the palette.
Designer's note

Empty query = Recents, never a blank pit. The first paint shows the last three things this account touched, so the palette is useful before the first keystroke. Groups appear in trust order — Events, then Guests, Vendors, Actions, Pages — because "find my event" is the dominant query in a multi-event account.

Group labels are Space Mono gold kickers; result rows are Hanken Grotesk. Every row carries a secondary line (table, category, date) because Filipino guest lists are full of namesakes — two Ramon Santoses are told apart by their table.

04 / 07

Lightbox — full-screen media, the one obsidian surface

Opens from any gallery grid — Papic uploads, the couple's gallery, a vendor's portfolio. The app is light-locked; the lightbox alone goes obsidian #17160F because photographs and clips read better against dark. This is a surface decision, not a theme.

Trigger
Tapping any media tile in a gallery grid. Opens at that item, with prev/next across the same set.
Dismiss
Swipe down (the media follows the finger, fades, releases past 120px) · Esc · the labelled Close button. Backdrop tap also closes — media browsing is casual, never destructive.
Focus
Focus moves to Close on open and is trapped; ←→ change media, Space plays/pauses a clip. Returns to the exact tile that opened it. role="dialog" aria-modal aria-label="Media viewer"
Scrim
Near-opaque obsidian rgba(23,22,15,.92) — the gallery must disappear so the photo owns the room. Scroll locked.
Mobile vs desktop
Both are full-bleed. Mobile: 3:4 stage, swipe left/right between items, pinch to zoom. Desktop: 3:2 stage, arrow buttons + keys, double-click zooms. Identical chrome top (counter · Close) and bottom (tags · scrubber).
Stacking
Tapping a tagged-person chip does NOT stack — the lightbox closes, then the guest's profile opens. Only a toast may appear over the lightbox (e.g. "Saved to your photos").
Designer's note

Everything on obsidian uses the four obsidian tokens only — #FBFAF7 text, #B6B9BE soft, #CBA766 accent. No terracotta on dark: it fails contrast and reads muddy. The gold accent carries play, scrub and chip-hover instead.

Clips get a scrubber and a timecode in Space Mono; the 10-second hard cap means the scrubber is short and honest. Tagged-people chips sit under the media — tags are Papic's soul and deserve first-class placement, but the chip navigates after close, so guests never lose their place in a stack of dialogs.

05 / 07

Pickers — return a value, never navigate

A picker is a field's overlay: it opens from a field, returns exactly one value into that field, and closes. It never routes anywhere. Three flavours shown — date, guest (with search), vendor (grouped by category) — all one component with different bodies. Selecting commits and closes in one gesture.

Trigger
The field itself (the whole field is the button, labelled, never icon-only). Enter/Space opens it from the keyboard.
Dismiss
Selecting a value (commit + close) · Esc · backdrop click · swipe-down on mobile. Dismissing without selecting leaves the field untouched — a picker has no "half-committed" state.
Focus
Focus moves to the search input (list pickers) or the selected/today date (date picker), is trapped, and returns to the field on close — where the committed value is announced via the field's live text.
Scrim
Mobile: standard scrim + scroll lock. Desktop anchored popover: transparent scrim (click-away layer) so the page stays visible for context; page scroll still locked while open.
Mobile vs desktop
Mobile 390: bottom sheet rising from the touch point, max 78% tall. Desktop 1280: 340px popover anchored under the field, drops 6px.
Stacking
A picker can sit above a sheet (e.g. date inside the vendor-booking drawer). A picker never opens another picker — compound values (date + time) are two adjacent fields.
Designer's note

Committing closes — no “Done” button tax. One tap chooses and closes; the gold-bordered field is the receipt. The old pattern (choose, then find the Done button) doubles every selection on a phone.

Dates render in Space Mono because numerals are data. The guest picker's second line (table · role) does the disambiguating, same rule as the palette. The vendor picker groups by the couple's own booked categories — caterer, photographer, coordinator, host/emcee, live band — in the order they appear in the plan.

06 / 07

Inline popover / tooltip — a whisper, not a doorway

The smallest overlay: an ⓘ explanation, the full text behind a truncated cell, what a status pill means. Non-modal, no scrim, outside-click to dismiss. The one iron rule: nothing load-bearing lives only here — the popover repeats or expands what the page already carries.

Trigger
Click/tap or keyboard-activate on an ⓘ button, a truncated cell, a status pill. Hover may preview on desktop, but click is the contract — touch has no hover.
Dismiss
Outside click · Esc · the trigger again (toggle). No close button needed at this size; auto-dismisses on scroll of the underlying page.
Focus
Not trapped — non-modal. Focus stays on the trigger; the popover is referenced via aria-expanded + aria-controls. If it contains a link, Tab moves into it, and Tab past the end closes it.
Scrim
None, no scroll lock. It is furniture on the page, not a room of its own.
Mobile vs desktop
Same anchored card at both sizes (max 300px), flipping above/below to stay inside the viewport. It never becomes a sheet — if the content is big enough to want a sheet, it is not tooltip content.
Stacking
Only one popover open at a time — opening a second closes the first. A popover under a modal overlay closes when the modal opens.
Designer's note

Never the only copy. Each demo pairs the popover with the same fact living in the page: the crew-meal ⓘ expands a rule the summary line already states; the truncated venue shows text the detail page owns; the status pill explains a state the ledger below also records. If deleting the popover would delete a fact, the design is wrong.

Popovers use ordinary page styling — cream, border, small shadow — deliberately humble so they never compete with real dialogs.

07 / 07

Banner / inline notice — the page speaking in its own voice

Not an overlay at all in the modal sense — banners live in the page flow (or docked to an edge) and never block. Three species: consent (privacy-preserving by default), conversion nudge (secure your plan), and degraded state (offline / syncing). Persistent when the condition persists; dismissible when the user may reasonably say "not now".

Trigger
A condition, not a click — first visit (consent), an anonymous draft worth saving (nudge), a lost connection (degraded). Banners appear with the page render or the state change, never mid-task.
Dismiss
Consent: only by choosing — Accept all or Decline non-essential, equal weight, one tap each. Nudge: labelled close, remembered. Degraded: not dismissible — it leaves when the condition does.
Focus
Never steals focus. Consent and degraded announce via a polite live region; the consent card is reachable in normal Tab order at the end of the page content.
Scrim
None. A consent wall with a scrim is a dark pattern; the page stays usable behind every banner.
Mobile vs desktop
Consent docks bottom (thumb reach), buttons full-width on mobile, inline on desktop. Nudge + degraded render as inline cards at the top of the content column at both sizes.
Stacking
Max one docked banner (consent wins) + one inline system banner (degraded wins over nudge). A nudge never appears while the app is degraded — asking someone to sign up while offline is noise.
Designer's note

Decline non-essential is one tap, same size, same row as Accept all. Ghost vs filled is hierarchy, not friction — both are single-action. This matches the privacy-preserving default the platform already commits to elsewhere (RA 10173 posture).

The nudge is gold-bordered (an offer), the degraded banner warn-coloured (a state). The degraded copy says what still works — "changes saved on this phone" — because reassurance beats apology at a venue with weak signal, which is exactly where the day-of surfaces run.

Global rules — apply to every archetype

Motion: every transition ≤240ms on cubic-bezier(.22,.61,.36,1). Sheets rise from the touch point (transform-origin set from the tap). Under prefers-reduced-motion, decorative movement is off and functional transitions reduce to fast opacity. No animation ever delays first input — panels are interactive from the first frame.

Accessibility: role="dialog" / "alertdialog" + aria-modal + aria-labelledby + aria-describedby on every modal; real focus traps; focus returns to the trigger on close; Esc closes everything except the destructive confirm; toasts announce via a polite live region; every control is labelled — never icon-only.

Market: bottom sheets, not centre modals, on mobile — the form Shopee, Lazada and GCash have made native here. Density reads as trustworthy; whitespace minimalism reads as unfinished.

Content: prices never appear in this layer as literals — a peso figure in a prototype is a defect. Where an amount would show, render the live catalog value or ₱—.
