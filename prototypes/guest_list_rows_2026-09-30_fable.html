Guest list — the rows

The list under the approved guest card (guest_card_and_list_2026-09-30 · guest_card_invite_simple_2026-09-30). Every row is the same small card: who they are, one line about them, their reply — then one Invite, one ⋯, and the status line. Invite sends the message, their link and their Digital ticket together, never a bare QR. Bride and groom rows have no Invite: they are the Host. AThe list at rest

  • Top: the title and + Add, one search field with Sort ▾ beside it, then four dropdowns — RSVP · Side · Role · Group. Each opens one list; never a row of pills. Sort ▾ is the shipped list: Importance (by role, in sections) · Last name · First name · Side · Group · RSVP · Table · Newest.
  • The counts line: 96 attending · 35 no reply · 58 to invite · 3 requests. The two in wine are the ones that need you.
  • Each row: their photo (or initials), the name in your Name style, one line under it — side · role · +N · Table — and the reply pill on the right: Attending · No reply · Maybe · Not coming. Tap the pill → one dropdown with those four (this replaces today's tap-to-cycle). A pair (the sponsors) is one row and one line.
  • Under the dashed line: the same pair as the card, Invite · ⋯, and the status: Not sent · Not linked or ✓ Sent Sep 30 · Linked. Invite opens the share sheet right here, without opening the card.

  • No table yet → the line simply ends at the role. Not coming → no table, ever.
  • Tap the name for the full guest card (the other designer's file: guest_card_details).

CSelect mode

  • Long-press any row to start. The title becomes 3 selected, with Select all 142 and Done. Each row gets a round check on the left; the Invite pair hides while you pick, so a row is just a thing to tick.
  • The bottom bar: Invite selected · Set group ▾ · Set table ▾ · ⋯. Under the count, plain words: 2 not yet invited.
  • Invite selected opens one share sheet per guest, in order — each with that guest's own ticket. On a computer, it makes one message you paste, then the tickets one by one.
  • Set group ▾ and Set table ▾ are one dropdown each (existing groups + New group…; tables 1–20 + No table).
  • ⋯ holds the rest, one list: Set side · Set role · Mark invited · Remove from list.
  • Bride and groom rows cannot be selected for Invite; they can for group and table.

DWhen people ask to join

  • Someone who opened your event link and typed their name is a request, not a guest yet. They are not in any count until you keep them.
  • When there are requests, one strip sits right under the title: 3 requests to join — From your event link — keep them, or link them to a name you already have. Review › opens the Requests page (already built: Keep · Link to a name · Not a guest).
  • No requests → no strip. The counts line still ends with requests only when the number is above zero.
  • The strip is the only place requests interrupt the list; they never appear as rows between real guests.

GThree rows checked

  • Tick a row's box (it shows on hover, and stays once anything is ticked). The header box goes half-filled; clicking it ticks everything shown — here the 35 with no reply — and says so: 35 selected.
  • The bar floats at the bottom, dark, one line: 3 selected · 3 not yet invited · Clear then Invite selected · Set group ▾ · Set table ▾ · ⋯ — the same four as the phone, in the same order.
  • Checked rows are washed gild, like the open row in F — same colour, because both mean "this row is in hand".

  • Escape or Clear empties the selection; the bar slides away.
