Static HTML · no JavaScript · CSS motion only · phone first (390 Classic · 375 Cyber Neon) · sample data · "Event Hub", never a site

What this is. The owner, pointing at the tag-shaped swatches in the Dress code scene (today: tall hole-punched tags with the hex under each): "we also want to provide 5 styles of how to present palettes" — then "is it possible that these palettes have an animation". Five looks for the SAME colours: A is today's tags and stays the default (a live page never changes unless the couple picks); B–E are the gap. Every look shows the same data the scene already holds — the Mood Board's main colours with their names and hex — and every look also shrinks to row size for the per-role rows under it (the Bride's row is drawn in each, with the illustrated gown from PR #6137). Each style comes with its own entrance, in CSS, that plays once when the palette scrolls into view and then holds still. Picking a look is one dropdown in the scene's panel. All five are free (why: § Notes).

Prototype-only motion note. In this file each entrance repeats every 4 s so you can watch it again — there is no Replay button because there is no script. In the Event Hub it plays once (the hub's arrive-once observer in pahina-motion.tsx). Anyone whose phone asks for less motion sees the colours already in place. The PNG beside this file is the resting look.

Notes

For the owner and the builder

Why all five are free. The owner's rule: FREE must be very easy; Pro is for heavier customisation. A palette look is a pick from a dropdown — the couple types nothing, uploads nothing and tunes nothing; the colours, names and hex are already theirs from the Mood Board. Drawing cost is CSS only. The one look that could carry a Pro tier is Fabric with the couple's OWN fabric photos on the squares (an upload, per colour) — that is a different feature, not one of these five. The same reasoning made the scene layouts free on 2026-09-29.

Where the pick lives. Beside the scene's layout pick: invitation_widgets.config_json.canvas.palette next to canvas.style, same sanitiser shape ([a-z][a-z0-9-]{0,31}), ids tags · fabric · chips · circles · ribbon, absent = tags ("Auto is an absence"). dress-code-widget.tsx takes it as a prop; the "You are Bride" specific view and the role rows (ROW_SWATCH) follow the same value at row size. The Mood Board's own palette-section.tsx is the source and is not touched.

Auto ink. Each colour picks the ink with the higher contrast against it — the choice outlineOf() in lib/role-figure.ts already makes for a figure's edge, but decided by contrast, not a 150 mean: Gold #B8934A is 149.7 on the mean and would be told "light ink" (2.8:1); by contrast it is dark ink (7.6:1). The names under Tags, Fabric, Circles and Ribbon sit on the PAGE and use the theme's ink; only Paint chips puts the name on the colour, so only it needs the per-colour ink — and Fabric's stitch and Circles' holes use it decoratively.

Motion, honestly. Five entrances, CSS @keyframes only, one colour 100 ms after the last, the whole thing under 1.2 s for six colours, then still — no loop in the Event Hub, no idle. It rides the hub's existing arrive-once observer (pahina-motion.tsx, .sn-arrive), so it plays when the palette scrolls into view and never again on that visit; reduced motion shows the colours in place. In this file only, each demo repeats every 4 s because a Replay control needs a script and this file has none. The PNG beside this file was captured with reduced motion forced — it is the resting look, not a frame.

What this file does NOT decide. (1) The row's one-word label — "Colours" is used because "Style" is the layout row on rd/scene-styles-fixed-parts. (2) Whether the Mood Board's own Palette part in the Maker → Details should also offer the look (it is the source, so probably not — one pick, in the scene). (3) The seventh colour, Charcoal, and the sixth, Slate, are sample colours, not the couple's — the real sample is Wine · Olive · Cream.
