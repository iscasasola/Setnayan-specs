SETNAYAN · Screen archetypes — Sheet, Wizard, Admin console

Three of the ~12 archetypes that govern all 401 routes. The sheet replaces "open a new page to do one small thing" everywhere; the wizard owns every multi-step flow; the admin table is the one place tabular density wins. Light-locked — reviewed on cream, shipped on cream.

Archetype sheet 02 · 2026-08-01 · Mobile 390 / Desktop 1280 · Prototype, not production

The response ladder — every pick, all three archetypes
01 · ≤100MS

Acknowledge

The picked element changes before any network call — gold border, filled tick, 2px lift. The finger never waits for the server.

02 · NOW

Commit optimistically

Dependent UI updates immediately: totals, seat counts, the CTA label. The screen behaves as if the pick already happened.

03 · ON RECONCILE

Reconcile — silent, or revert

Success says nothing. Failure reverts the visible change and shows a toast naming exactly what was undone. This is the beat everyone forgets.

04 · ≤240MS

Reveal consequence

Anything newly relevant animates in; anything now irrelevant animates out. Seat-position chips appear the moment a table is chosen.

Try it live: the assign-table sheet in Archetype 01 runs all four beats. Tick "simulate reconcile failure" under the phone, pick a table, and watch beat 03 revert the pick and name it in a toast. The admin console's unmatched row does the same on Approve.

Archetype 01 · Sheet

Every secondary action happens in a sheet

Governs · every secondary action on /dashboard/[event]/guests · /vendors · /schedule · /budget · /services — ~180 customer + vendor routes

Bottom sheet on mobile, side drawer on desktop. The list you were reading stays visible behind the scrim, so "assign a table" is a ten-second detour, not a navigation. Snap points: peek (glance the header), half (pick from a list), full (fill a form). Swipe down or tap the scrim to dismiss. A sheet may stack exactly one child sheet — always a creation subtask.

Empty teaches; Denied redirects. Empty is warm — gold accent, one terracotta action that fills the void. Denied is cool — link-blue band, shield, the role that failed, and a person to ask. Denied renders only from a permission probe, never inferred from count===0.

Designer's note — Sheet

  • The sheet is the default, the page is the exception. A route change is reserved for a change of subject. Assigning a seat, logging a payment, editing a field — same subject, so the context stays lit behind the scrim.
  • Snap points map to intent: peek = confirm what's open, half = pick from a list (thumb reaches every row), full = type into a form. The keyboard pushes the sheet to full automatically.
  • Stack depth is exactly two. The only legal child sheet is a creation subtask ("New table…"). If a flow wants a third level, it is a wizard, not a sheet.
  • The footer is sacred: one summary line, one terracotta CTA whose label names the outcome ("Seat Aling Nena at Table 4" — never "OK"). Destructive actions sit below it in negative, and always arm on first tap.
  • Dirty sheets resist dismissal. Swipe-down on unsaved input snaps back to half and pulses the footer. Data loss must be a decision, not a gesture.
Archetype 02 · Wizard

One decision per screen, progress you can read

Governs · /onboarding · /events/new · /dashboard/[event]/services/[sku]/apply · vendor registration — every flow with 2+ decisions (~20 flows)

Five steps, five decisions: occasion → date → place → people → done. Progress is a rail of named beads, not a percentage — each bead is a decision you made, and the last one is the brand promise. Back is always available and always lossless: panels persist, the draft lives on-device, and the exit label says so out loud.

Designer's note — Wizard

  • One decision per screen because the audience arrives from Shopee, GCash and Facebook — flows there never show two questions at once. A stacked form reads as homework; a single question reads as a conversation.
  • Progress is earned, never percentaged. The beads carry the names of decisions (Type · Petsa · Lugar · Tao · Tapos), fill as you decide, and the last bead cashes the brand promise: the done screen literally says Set na 'yan.
  • Back is a slide, not a reset. Panels persist in the DOM and the draft persists on-device, so back is lossless by construction. Even the exit button promises it: "Exit — draft stays saved."
  • Pickers beat keyboards. Occasion, date and city are taps; typing exists only where the answer is a proper noun (the celebrants). Every picker acknowledges ≤100ms and reveals its consequence ≤240ms — the date reveals its weekday, the city reveals its venues.
  • The CTA narrates the choice ("Continue — Kasal", "Continue — 12 Hun 2027"). A label that echoes the decision is the cheapest confirmation dialog ever shipped.
Archetype 03 · Admin console table

The one place tabular density wins

Governs · /admin/* — ~108 internal routes · replaces 33 raw <table> elements · Setnayan staff only

Internal tool, optimised for speed over beauty: sticky header, zebra-free rows, hover-revealed actions, inline edit, full keyboard navigation, column sort, bulk select, filter bar. Motion budget here is near zero — a 120ms opacity fade on row actions and nothing else. Shown on the payments reconciliation queue, the busiest of the 108.

Designer's note — Admin console

  • Zebra is gone on purpose. Hairline borders + hover tint carry the row; zebra stripes fight the two tints that actually mean something — selection (blue) and hover (gold).
  • Density is the feature: 38px rows, mono right-aligned numerals, 9 columns without wrapping. This surface is staffed, trained, and used eight hours a day — Shopee-seller-center density, not marketing airiness.
  • Keyboard first, mouse optional. Every mouse action has a key, the focus ring is always visible (link blue, 2px), and the legend is one keypress away. Approving 30 payments should be ↓ A ↓ A ↓ A.
  • Optimistic with a named revert. Approve flips the pill instantly; a failed write flips it back and the toast says which ref reverted. Silent success, loud undo — same ladder as the customer side.
  • Minimal motion is a speed budget: one 120ms opacity fade on row actions. No slides, no springs — anything slower than the operator's hands is friction.
